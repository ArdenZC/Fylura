# v3.40 七项动效性能报告

## 1. 测量方法

- Playwright Chromium headless + CDP：`Performance.enable`、
  `Emulation.setCPUThrottlingRate`、`Performance.getMetrics`。
- 页面内注入持续 `requestAnimationFrame` 采样器与
  `PerformanceObserver("long-animation-frame")`。
- 7 个场景各重复真实交互 3–6 次；每场记录动作是否真实生效、动画 id/时长、
  结算后的 DOM/状态，失效场景直接判 `INVALID` 并退出。
- 视口 1440×900，DPR 1，`Win32` 平台模拟，`?browser-mock=1` managed root。
- Chrome 版本见 `../manifest.json`；每场景新建页面，避免互相污染。
- 帧间隔去掉首尾各 2 帧；掉帧定义为 `> 16.7ms × 1.6`。

复现：`node scripts/runV340Perf.mjs`。

## 5. 分析与本轮修复

1. **主区 `backdrop-filter` 是此前所有浮层 30fps 的根因。** 移除前菜单/搜索/
   预览在 1× CPU 下稳定 p50 33.3ms；主区 93% 不透明，20px 模糊几乎不可见，
   移除后 p50 16.7ms。侧栏与标题栏玻璃保留（`v340-shell.css`）。
2. **空第三列使 Inspector 打开时列表只有 370px**，列数从 4 掉到 2；移除后
   列表 658px，列宽与原型对齐，页面切换/视图切换不再触发多余列重排。
3. **侧栏 4× p50 33.3ms**：200ms 内 `grid-template-columns` 每帧重排主区，
   与原型 4× Windows 的 16.7/50（layout 290ms）相比 p95 更高，但 layout 总量
   155ms 更低；1× 为 16.7/16.8、0 掉帧。该项在低端 4× 下属于可感知成本，
   未用删除侧栏动画的方式换取数字。
4. **确认层 4× LoAF 234ms**：3px 遮罩模糊 + 卡片 + ghost 退场；原型同样在
   确认层出现 24 掉帧，并明确记录「模糊值得保留」。本轮保留 3px 模糊。
5. **窗格 4× 最大长帧 597ms**：四窗格一次渲染 3 个新窗格（每个含列表/空态），
   与原型「三格各渲染 20+ 行」同源；1× 下 3 掉帧、p95 16.8ms。
6. **页面切换 4× 最大长帧 218ms**：整页 React 重建，原型同场景也有 146ms
   LoAF（4× Win）。未做页面级假缓存。

## 6. 结论与边界

- 1× CPU 下七项全部 p50 16.7ms；除确认层 8 帧、窗格 3 帧外无掉帧。
- 4× CPU 下侧栏/确认/页面/窗格出现 100–150ms p95，属于降速环境的主区重排
  与整页重建成本；没有发现由动效实现导致的持续 30fps（已通过移除无效模糊修复）。
- 未测：真实 macOS 原生窗口、真实磁盘/网络设备、安装包；这些仍归 #487。
