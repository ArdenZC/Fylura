# v3.40 七项动效性能报告（PR B 复测）

## 1. 测量方法（本轮修正）

- Playwright Chromium + CDP：`Performance.enable`、`Emulation.setCPUThrottlingRate`、
  `Performance.getMetrics`；页面内 rAF 采样 + `PerformanceObserver("long-animation-frame")`。
- **只看动画活动窗口**：每个 rAF 帧记录 `document.getAnimations().length > 0`，
  p50/p95/掉帧只统计实际有 CSS transition / WAAPI 在跑的帧；空闲等待（`idleFrames`）
  不参与分位数，避免把“等 300ms”稀释成好看的 p50。
- 七场景都验证动作真实生效（pane 数、菜单 DOM、弹窗、视图模式、动画 id/时长），
  失效直接 `INVALID` 并退出。
- 1440×900，DPR 1；额外用 DPR 2 采样四窗格。Win32 模拟，`browser-mock=1` managed root。
- Chrome 151.0.7922.34。复现：`node scripts/runV340Perf.mjs`。

## 2. 预设标准

| 指标 | 1× | 4× |
|---|---|---|
| p50 | ≤16.7ms | ≤33.4ms |
| p95 | ≤50ms（确认层允许 50ms，因其 3px 模糊） | ≤250ms |
| 掉帧 | 单场景 ≤10 帧 | 允许降速长帧，但 LoAF 最长 ≤600ms |
| 动作 | 必须 verified | 必须 verified |

|---|---:|---:|---:|---:|---:|---:|---:|---:|

- p50 全部 16.7；p95 ≤250；最长 LoAF 542ms（四窗格）。
- 确认层 1× 掉帧 8 / 4× 15：3px 模糊是设计保留项（原型同样 24 掉帧），未删除。
- 侧栏 4× p95 166.6ms、30 个 LoAF：200ms 内 `grid-template-columns` 每帧重排主区；
  layout 总量 161ms 低于原型 4× Win 的 290ms，但 p95 更高，标记 **PARTIAL（低端 4×）**。

## 6. 与 PR3 基线对比（相同场景、相同机器）

| 场景 | PR3 4× p50/p95 | 本轮 4× p50/p95 | 说明 |
|---|---|---|---|
| 页面切换 | 16.7 / 116.6 | 16.7 / 116.7 | 持平 |
| 侧栏收展 | 33.3 / 133.4 | 16.7 / 166.6 | p50 改善，p95 受运行噪声/真实活动窗口更严格影响 |
| 菜单弹出 | 16.7 / 83.4 | 16.7 / 100.0 | 活动窗口统计更严格（空闲帧不再稀释） |
| 确认层 | 16.7 / 133.4 | 16.7 / 150.0 | 同上 |
| 目录树折叠 | 16.7 / 16.8 | 16.7 / 16.8 | 持平 |
| 列表↔网格 | 16.7 / 33.4 | 16.7 / 116.7 | 活动窗口包含过渡尾帧，数字更诚实 |
| 窗格布局 | 16.7 / 150.0（max 597ms） | 16.7 / 216.7（max 542ms） | 最长 LoAF **597→542ms**；p95 因双帧统计变化 |

本轮修复：窗格 1→4 改为逐帧揭示新窗格，避免一次 commit 渲染三个窗格；最长 LoAF 降约 9%。
4× 四窗格仍有一个 500ms 级长帧（React 同时激活 3 个窗格的控制器），标记 **PARTIAL**。

## 8. 结论

- 1× 七项全部达到预设标准；4× p50 全部 16.7、p95 ≤250、最长 LoAF 542ms。
- 没有通过删除关键动效换数字；唯一性能取舍是移除主区 93% 不透明下的无效 20px 模糊（PR3）。
- 侧栏 4× p95 与四窗格 500ms 长帧为 **PARTIAL**；原生真机帧率仍 NOT_TESTED。
