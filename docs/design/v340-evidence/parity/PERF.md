# v3.40 七项动效与四窗格性能报告（最终聚焦整改）

## 1. 测量方法

- Playwright Chromium + CDP：`Performance.enable`、`Emulation.setCPUThrottlingRate`、
  `Performance.getMetrics`；页面内 rAF 采样 + `PerformanceObserver("long-animation-frame")`。
- **只看动画活动窗口**：每帧记录 `document.getAnimations().length > 0`；p50/p95/掉帧只
  统计实际有 CSS transition / WAAPI 的帧，空闲等待不参与分位数。
- 七场景都验证动作真实生效（pane 数、菜单 DOM、弹窗、视图模式、动画 id/时长），
  失效直接 `INVALID` 并退出。
- 1440×900，DPR1；额外 DPR2 四窗格。Win32 模拟，`browser-mock=1` managed root。
- Chrome 151.0.7922.34。复现：`node scripts/runV340Perf.mjs`。
- **测量环境说明**：browser fixture 只在 Vite dev（`import.meta.env.DEV`）下加载；
  生产构建缺少 Tauri 运行时，会进入“无法访问数据库”而不是 fixture。因此以下数字是
  **Chromium dev-server + 4× CPU**，包含 dev JSX 开销，属于偏保守的上界；它不是
  安装版 / 生产构建数据，原生性能仍归 #487。
- 长帧定位：`scripts/profileV340LongFrames.mjs` 单独执行 5 次配对运行，记录
  p50/p95、最长 LoAF、脚本归因、Layout/Style 总量。`--profile` 才启用 CPU 采样；
  采样本身会增加开销，所以绝对数字只用无采样运行，采样数据只用于判断任务类别。
  输出：`perf/long-frames-4x.json`（无采样，官方数字）与
  `perf/long-frames-4x-profile.json`（采样归因，绝对数字含开销）。

## 2. 预设标准

| 指标 | 1× | 4× |
|---|---|---|
| p50 | ≤16.7ms | ≤33.4ms |
| p95 | ≤50ms（确认层允许 50ms，因其 3px 模糊） | ≤250ms |
| 掉帧 | 单场景 ≤10 帧 | 允许降速长帧，但 LoAF 最长 ≤600ms |
| 动作 | 必须 verified | 必须 verified |

  宽度变化不再触发四个窗格 workspace 的重复 React 渲染，主区只重排可见窗格。

## 5. 四窗格 1→4 冷启动（5 次配对）

验收脚本的“窗格布局切换”按 2→4 执行；用户从单窗格直接点 4 会同时揭示三个新窗格，
更重，因此单独测量：

| 指标 | 侧栏收展 | 四窗格 1→4 |
|---|---:|---:|
| p95（5 次中位） | 50.0 | 150.1 |
| p95（最差） | 66.7 | 200.0 |
| 最长 LoAF（中位） | 106 | 585 |
| 最长 LoAF（最差） | 117 | 609 |
| 动作 verified | 5/5 | 5/5 |

- 1→4 的 585ms 中位低于 4× 600ms 门槛，但 5 次中有 1 次 609ms 超过门槛，**PARTIAL**。
- 长帧全部是 `dispatchDiscreteEvent` 的 **Script** 任务（React commit）；Chrome CPU
  profile 顶部为 `jsxDEV` / `createElement`，不是 Layout/Paint（LoAF 的 style/layout
  阶段在脚本结束后才开始）。
- 每个新窗格首次可见仍需一次完整 workspace render；逐帧揭示已把一个 4 窗格 commit
  拆成“每帧一个新窗格”，剩余成本是新窗格首帧本身。继续压缩只能延迟内容或减少窗格，
  不符合本轮约束。

## 9. 结论与剩余风险

- 七项 1×/4× 在活动窗口统计下全部达到本轮门槛；2→4 的四窗格长帧从 542ms 降到 371ms。
- 1→4 三窗格冷揭示 585ms（中位）/ 609ms（最差，1/5 超门槛）→ PARTIAL。
- 数字来自 Chromium dev-server + browser fixture，不是 Tauri 生产构建或安装版；
  macOS WKWebView、真实缩略图/Quick Look、原生合成器未测，#487 暂缓。
- 未删除、缩短或跳过任何原型要求的主要动画；未减少真实 Pane 数量或改变 Pane 身份。
