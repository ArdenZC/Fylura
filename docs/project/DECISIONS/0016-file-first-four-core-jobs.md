# ADR-0016 — Fylura 文件优先的四项核心任务与首次使用体验

**状态：Owner 产品方向已确认（2026-11-01）；P0 首次引导 / Files 唯一默认入口 / 显式 Global Search 授权已实现，等待 Owner 与原生验收。**
**适用范围：** 产品信息架构、首次启动、文件工作空间、AI 整理、AI 垃圾清理、全局搜索授权和开发优先级。
**决策记录：** [#527](https://github.com/ArdenZC/Fylura/issues/527)；功能与交付事实以 [#512](https://github.com/ArdenZC/Fylura/issues/512) 和当前代码/CI 为准。
**实现记录：** [UX-04 首次引导与 Files 唯一模式](../tasks/UX-04-FILE-FIRST-ONBOARDING.md)。

> 此 ADR 固定**目标产品体验**，不表示功能已完成、已通过原生验收、已获发布许可，亦不授权修改安全/隐私/文件系统执行权威。若与历史 W0/W2 或 V4.3 的用户可见双模式、强制选文件夹、Cleanup AI 仅疑难复核的文案冲突，以本 ADR 的**未来 UI 产品方向**为准；历史文档仍保存当时实现/验收事实。

## 1. 产品定位与四项核心任务

**Fylura 是 Windows 与 Apple Silicon macOS 上本地优先的高效文件管理工具，辅以快速全局搜索、按需 AI 整理与 AI 垃圾清理。** 首先让普通文件管理好用；只有需要语义理解时才调用 AI。

| 用户可理解的能力 | 核心结果 | 用户是否必须配置 AI/长期管理 |
| --- | --- | --- |
| **文件管理（Files / Browse）** | 浏览系统文件夹、标签页、双栏、文件篮、预览、复制/移动/重命名、批量操作、符合能力边界的目录比较与历史/恢复 | **否** |
| **全局搜索（Global Search）** | 在明确授权的受支持本地磁盘/范围内快速定位文件；Smart Lean 优先排除有证据的低价值系统/缓存/依赖数据 | **无需 AI；索引必须用户明确启用** |
| **AI 智能整理（Organize）** | 任意选定的文件夹/文件集合 → 有授权的数据分析 → AI 整体分组方案 → 异常审核 → 统一执行/历史恢复 | **需使用时授权 AI；不要求长期管理** |
| **AI 垃圾清理（Cleanup）** | 范围内确定性候选事实 → AI 语义分析及整体清理方案 → 分风险审核 → 可执行部分 Safe Trash/历史恢复 | **需使用时授权 AI；不要求长期管理** |

普通文件操作（如无冲突的用户明确 Copy/Move）遵循既有流畅操作标准，不应反复弹出 Prepare/Confirm 对话框；这不取消后台 authoritative Preview、重验证、Journal，也不放宽高风险/删除确认。

## 2. 文件工作空间：对用户只展示一个模式

- **只展示 Files / 文件管理（现有 Browse）**：真实系统文件夹浏览、双栏、标签、文件篮、Quick Preview、常用位置和普通文件操作；默认启动进入可立即使用的 Files，未建任何扫描范围也可工作。
- **完整保留已开发的 Managed Library**：Library Mode 的组件、Query V2、LibrarySelectionV1、数据、scan roots、watchers、标签、Saved Views、既有相关 API、迁移兼容、测试及需要的管理入口/操作边界。现阶段不把“Library / Browse”切换当成普通用户默认界面的一部分。不得删除持久化记录或暗中转换现有授权；已有用户数据须可安全保全并在未来恢复入口时可用。
- Browse 与 Managed Library **底层权威仍然区分**，不合并数据库与服务，也不新建第二套文件操作引擎。Browse 不因浏览一个目录而加入 Managed roots 或触发长期 AI 分析。
- **长期 AI 维护不再是当前产品承诺/默认能力**；已有自动化、Managed AI 与语义证据保留，持续分析、Embedding、Preference Memory 等后续能力需先证实实际用户价值、成本与资源表现。
- “接管文件管理”指 Fylura 内提供类似 Finder/Explorer 的完整日常工作方式，**不代表默认替换系统默认文件管理器、拦截系统快捷键或迁移用户文件**。

## 3. 首次启动与再次发现

**短而可跳过的四场景引导**，优先展示真实产品界面或经确认的能力，不能只在一页放四张空泛卡片：

1. **文件管理作为主角**：用有代表性的双栏、标签页、文件篮、预览与常见批量工作流展示日常价值。对未完成的外部拖放、深同步等不作已交付承诺。
2. **AI 整理**：演示桌面/下载目录按用途分组、整体审核和恢复，不要求先添加 Managed Library。
3. **AI 清理**：演示 AI 解释的分组清理方案、预计空间、风险分类、Safe Trash 与恢复。
4. **全局搜索选择**：说明将对**列出的受支持本地磁盘**建立轻量元数据索引，默认 Smart Lean，初建索引的时间/资源与增量更新；提供**启用**和**暂不启用**、必要时逐卷选择，Settings 中可改范围、暂停或关闭。不得声称未经验证的全部磁盘/系统文件都会被覆盖。

用户**任何时候都可跳过并直接进入 Files**；跳过需持久生效，不得反复弹窗、自动入库、索引卷、读取 AI 内容或启动后台扫描。无配置 AI 的用户可以完整使用 Files；首次打开 Organize/Cleanup 时再提示模型就绪、内容/云端数据授权和实际费用/资源边界。帮助/了解 Fylura 允许用户自愿重新打开介绍。

## 4. AI 整理：审核方案而非逐文件审批

用户从 Files 当前目录、选中项、File Basket 或 Organize 入口开始任务；**可选择任意受支持的单次文件范围**。技术上须扩展现有 Organization Plan 的一次性来源接入，不能要求先长期加入 Managed Library；复用现有身份校验、语义评估、持久 Plan、Dry Run、Journal、Restore。

建议流：选择范围和可选意图 → 有界元数据/必要且已授权的内容分析 → AI 给出**按用途/目标目录分组的方案**（文件数/大小/去向/原因/置信度） → **只提示例外**（冲突、低置信、敏感、改变、权限/目标不明确） → 用户可以按组接受、排除、改目标或展开修改单项 → 统一执行预览与一次确认 → 结果/History/Restore。

安全、清楚且后端认可的组可默认纳入执行计划，但**不能**因 AI 自称高置信而越过后台真实 revalidation，不能静默覆盖或替用户处理未解决的风险。普通用户不应逐文件点击批准、重复批准相同类型的安全移动。

## 5. AI 垃圾清理：AI 必须提供整体分析和方案

Cleanup 是与 Organize **同等重要且独立**的核心任务，不能仅把 AI 当成“疑难候选重新检查”的可选按钮。目标流：

选定清理范围 → 确定性检测器提供候选、大小、重复/缓存/临时文件等事实 → 在独立 Cleanup AI 授权下对有关候选作语义评估、生成**有理由和空间收益的分组清理方案** → 区分**可批量清理 / 需要用户确认 / 不建议或不能处理** → 用户审核整体并可展开例外 → 批量 Safe Trash → 结果与恢复。

**AI 不能证明文件可安全删除、不能提高原本不符合策略的候选执行资格、不能绕过敏感项审核或授权永久删除。** 高风险/歧义项不能默认选中；模型不可用时如实表示语义流程暂不可用，不能让旧 Rules 静默接管语义判断。避免每文件重复调用 LLM；优先复用 current assessment 和目录上下文，在用户实际发起任务时才消耗资源。

历史 [UI V4.3 Cleanup §14.3](../../design/UI_UX_V4_3_SPEC.md) 中“AI optional contextual review”仅作为当时已实现 UI 的历史记录，**不再等于目标完整的 AI Cleanup 产品体验**。

## 6. 全局搜索、低价值索引与 Zen Zero

- 第一次明确征得**每个受支持来源/卷的授权**后才启动全局索引，不因进入 Files 而自动授权整个 C 盘；历史用户原有授权/索引状态须迁移和展示清楚。
- Smart Lean 需要扩大**有证据**的系统/应用/缓存/依赖低价值过滤覆盖面，特别核验高数量系统目录，但不能粗暴隐藏用户文档、工程、少数确有价值的应用数据；区分原生来源遍历量与真正数据库索引写入量。
- Settings 中提供全局索引开关、卷/路径范围、覆盖状态和资源信息。权限不足、离线和索引未完成需明确说明，不能伪称“搜不到就是不存在”。
- 无主动整理/清理任务时不得因隐藏 Managed Library 或欢迎弹窗而自动触发昂贵的 AI、内容读取、扫描或高频轮询。遵守现有 Zen Zero 预算，不额外采购付费方案作为前提。

### 实施顺序（产品价值顺序，不代表日期/现时 Track 激活）

**P0：** 冻结本方向；完成首次引导/Files 唯一默认入口与显式 Global Search 授权交互；保留 Managed Library 数据兼容。
**P1：** 文件管理高频路径打磨、双平台目录/剪贴板/文件篮/任务反馈及可恢复性。
**P2：** 在现有 AI/Plan/Preview/Recovery 权威上打通“一次性 AI 整理”与“AI 分析后的分组清理”，做到少操作、异常优先、可追溯。
**P3：** Smart Lean 真实低价值覆盖、Zen Zero 长期运行与 Win/macOS 原生全功能矩阵；Global Search 性能独立跟进。
**P4：** 仅在用户价值和成本得到实测证明后，考虑重新面向用户开放长期智能 Library/语义关系/偏好记忆；不得自动启动。

**交付验收以真实用户任务而非组件数量为准。** 必须测：首次安装/跳过/重启、未授权无索引调用、旧用户已有 Managed Library 数据完整、Browse 零配置可用；桌面/下载目录 AI 整理整组审核、冲突例外、恢复；Cleanup AI 分组建议、高风险不默认选中、Safe Trash/恢复；无 AI/离线/权限不足/部分来源状态；跨平台真实 GUI 和可观察用户点击/决策次数。具体合并/Release 状态仍由项目跟踪、CI、Owner 验收决定。

## 8. 拒绝的替代路线

- 为了简化 UI **直接删除** Managed Library、标签、Saved Views 或迁移记录。
- 将所有文件夹加入长期管理或默认全盘 AI 分析，以提供“智能”体验。
- 把全局搜索索引授权、长期 Library 管理和单次 AI 整理范围合并为一次选择文件夹。
- 把 AI 整理与垃圾清理合并成自动删除功能，或让 AI 单独拥有文件系统修改权限。
- 以几张功能卡片代替真实文件管理能力展示，或让首次使用成为不可跳过的配置向导。

**本 ADR 完成仅代表产品方向写入仓库；应用交互与功能缺口的实现、实机 QA 和合并必须独立验收。**
