## 0. 如何使用这份 PRD

本文件回答「为谁解决什么问题、用户应该如何完成任务、什么体验才算交付」。它不是开发计划、实现说明、进度台账、CI 证据、接口契约或新的审批流程。

- **方向依据**：[ADR-0016](DECISIONS/0016-file-first-four-core-jobs.md) 和 [PRODUCT_MAP](PRODUCT_MAP.md)。
- **实现与待办事实**：[Issue #512](https://github.com/ArdenZC/Fylura/issues/512)、当前代码和测试；计划与进行中状态分别查看 [ROADMAP](ROADMAP.md)、[STATUS](STATUS.md)。
- **设计依据**：[v3.40 前端收敛 #574](https://github.com/ArdenZC/Fylura/issues/574) 及其 DESIGN-SPEC / MOTION / HANDOFF 原型包。历史 V4.3 规范不能覆盖较新的产品方向。
- **技术边界**：[ARCHITECTURE_MAP](ARCHITECTURE_MAP.md) 和既有文件操作、授权、Journal/Restore 权威。
- **实际发布资格**：[原生实机整体验收 #487](https://github.com/ArdenZC/Fylura/issues/487)，不能用 CI 通过、浏览器模拟或安装包生成代替。

本文的「应当」表示 v1.0.0 目标体验，不等于当前已经实现或通过原生验证。与已确认 ADR 冲突时以 ADR 为准；与既有工程安全/数据权威冲突时不通过 PRD 擅自修改，需针对具体问题处理。

## 1. 产品概述

### 1.1 一句话定位

**Fylura 是以日常文件管理为基础、以全局搜索和按需 AI 整理/清理为增强能力的本地优先桌面文件管理器。**

Files 应当能够承担 Windows Explorer / macOS Finder 中用户常见的日常文件管理任务，但不替换操作系统 Shell 进程、不接管系统关联、不要求迁移文件到 Fylura 专有库。

### 1.2 用户问题

1. 文件散落在不同磁盘、文件夹、移动设备和已挂载位置，定位和跨目录移动不够顺手。
2. 多文件批量操作中，冲突、错误和操作后恢复需要清楚而可靠的反馈。
3. 按普通文件名搜索不足以快速找到散落在授权范围内的文件，但常驻扫描不能不透明、不可控。
4. 下载目录、桌面和工作资料容易混乱；用户希望一次看到合理的分类与去向，而不是逐文件点确认。
5. 清理空间时不容易判断什么能删、为什么能删，以及误操作后如何恢复。

以上是当前产品设计所依据的**问题假设**，尚非来自已完成的正式用户访谈或规模化定量研究。

### 1.3 目标用户（待真实使用反馈验证）

- **主要用户**：Windows / macOS 上频繁浏览、搜索、整理和搬运本地文件的知识工作者、学生、教师、开发者及内容工作者。
- **高频场景用户**：同时操作多个目录、外置盘、已挂载 NAS 或云盘客户端目录的人。
- **AI 增强场景用户**：需要处理下载、桌面、项目资料的分组整理或存储空间清理，但希望保留人工最终控制权的人。

不以企业级 DLP/审计平台、云网盘服务或无人值守 AI Agent 为 v1.0.0 的主要定位。

### 1.4 核心产品承诺

- 不配置 AI、不建立 Managed Library，也能立即进入 Files 完成基本文件管理。
- 用户授权后，在所选受支持范围内使用 Global Search；索引状态和范围可理解、可调整。
- Organize/Cleanup 提供**整体方案、按组审核、异常优先、少确认**，不是 AI 每处理一个文件就弹一次窗。
- 操作结果可见；支持的文件变更可从 History 找回并通过现有恢复机制处理。
- 同一品牌下保持平台习惯：Windows 更接近 Explorer 的浏览交互，macOS 尊重 Finder 的平台特性。

## 2. v1.0.0 范围和优先级

| 等级 | 能力 | 目标结果 |
| --- | --- | --- |
| P0 | Files 日常文件管理 | 在 Fylura 中完成打开、定位、浏览、多选、复制、移动、重命名、删除/恢复等高频任务 |
| P0 | Windows/macOS 本机体验 | Windows 和受支持的 Apple Silicon macOS 安装版可真实使用，无需回到原生管理器完成基础路径 |
| P0 | Global Search | 用户显式授权的本地范围可查找、定位，并查看索引/覆盖状态 |
| P0 | AI Organize | 从一次性选定范围生成按组整理方案、可修改/排除、执行并追溯结果 |
| P0 | AI Cleanup | 对候选提供事实、风险、可选 AI 解释、批量确认、Safe Trash 与恢复 |
| P0 | History / Restore | 用户能理解刚才改了什么，支持的操作能撤销或恢复，失败状态不误报 |
| P1 | 体验优化 | 更精细的空状态、提示、快捷键、动效、响应式和辅助能力；不阻止 P0 缺口的优先处理 |

P0 表示产品范围中的主要用户结果，并非宣布全部已通过验收。是否达到 v1.0.0 发布资格以 #487 的准确版本原生结果和发布决定为准。

### 2.1 本版本不承诺

- 替换 Windows Explorer / Finder 的系统 Shell，成为操作系统文件管理器进程。
- 无授权扫描所有磁盘、自动把浏览过的目录加入 Managed Library 或默认运行 AI。
- 直接接入所有云服务账户的 OAuth、独立网盘同步引擎；优先支持系统已挂载且能力允许的位置。
- Linux、Intel Mac、Universal Binary / Rosetta。
- 全自主、长期运行、无人审批的文件 Agent；长期语义记忆、全面 Embedding/RAG/OCR 系统。
- 对所有外部设备、所有云占位文件、所有文件类型和回收机制保证完全相同的行为。
- 尚未测得的搜索速度、节省空间、AI 准确率或“零资源开销”营销承诺。

## 3. 产品信息架构与界面

### 3.1 全局与局部导航分离

- 全局应用导航：Files、AI Organize、AI Cleanup、History；Settings 作为次级功能，其他高级能力按需露出。
- **Global Search 仅从窗口顶部搜索框和 Ctrl/⌘+K 触发**，不设重复的侧栏搜索入口。
- Files 内的**文件位置栏独立**，仅包含常用位置、真实文件夹树、磁盘/外设、网络位置、收藏等，不与 AI/History/Settings 混排。
- Files 为首次启动和重新打开应用的默认主要目的地；Overview 不能遮挡进入文件管理。
- 文件列表优先占据有效空间；Inspector 可折叠，工具栏不应堆叠过高。

### 3.2 平台差异

- Windows：符合资源管理器用户对文件列表、详情列、右键菜单、剪贴板、快捷键及多窗格的习惯。
- macOS：符合 Finder 的窗口控制、列视图、键盘组合和浏览习惯；Finder 栏式显示模式**不等于**独立文件窗格。
- 两端共用品牌、任务含义和主要能力，但不强行模仿另一平台；真实原生安装版分别验收。

### 3.3 设计交付

以 Owner 已认可的 v3.40 原型与 DESIGN-SPEC / MOTION / HANDOFF 为视觉与交互基准。此 PRD 不重新绘制原型、不把原型中的模拟文件数组或伪操作作为实现要求。若原型与现行产品定义冲突，以明确的后续产品决策为准。

## 4. 核心用户流程与需求

### FR-00 首次启动与零配置价值（P0）

**用户目标**：第一次打开就能管理真实文件，而不是先配置 AI、索引库或多个权限向导。

预期流程：
1. 打开应用，看到可跳过的简短介绍：Files、AI Organize、AI Cleanup、Global Search。
2. 用户可直接跳过，进入 Files，打开受支持的本地文件夹并正常操作。
3. Global Search 以清楚的提示询问是否启用元数据索引，列明受支持来源/卷和默认低价值过滤；用户可启用、选择范围或暂不启用。
4. 未配置 AI 时，Files 仍可用；进入 AI 任务时才解释提供方、授权、数据共享边界与成本条件。
5. 跳过后不反复强制引导；可在帮助入口主动重看介绍。

验收：
- [ ] 没有 AI Key、Managed Root 或 Global Index 来源授权时能进入真实 Files。
- [ ] 跳过引导不会触发未授权的磁盘索引、Managed Scan、AI 内容分析。
- [ ] 用户能找到当前是否启用搜索及其来源范围，关闭/暂停后状态如实显示。
- [ ] 首次体验不对未验证的平台能力或性能作超出事实的承诺。

### FR-01 Files：基本浏览、定位与呈现（P0）

**用户目标**：在一个可信、流畅的工作区中查看并管理真实文件。

需求：
- 打开真实磁盘、文件夹、常用位置和系统已经挂载的受支持位置；路径导航、前进/后退、历史记录能按照当前窗口/窗格工作。
- 双击/Enter 打开文件或进入文件夹；文件由系统默认关联应用打开；空格键触发 Quick Preview；提供符合平台习惯的 Open/Open with/Reveal。
- 列表与网格展示；可切换显示隐藏文件。常用详情列包含名称、类型、大小、创建时间和修改时间。
- 列表可按相应表头升/降序排序、文件夹优先；分页/滚动后的显示不能只对当前加载页排序。
- 支持多选、范围选择、全选、右侧详情 Inspector 的展开/折叠。
- 单个 Files 标签可切换 1–4 个独立文件内容窗格；每个窗格独立路径、选择、排序、焦点和历史，窄窗口提供可用切换方式。
- 关闭再打开时，适合持久化的窗口/窗格布局恢复，不把旧单/双栏会话无故丢弃。

验收：
- [ ] 在 Windows 和 macOS 安装版中，各完成打开文件、浏览多级目录、查看属性、排序和多选。
- [ ] 1、2、3、4 窗格切换不串路径、不串选中项、不错误执行到非目标窗格。
- [ ] 搜索栏、文件位置栏、全局导航的职责与视觉层级清楚。
- [ ] 权限不足、路径不可用、设备断开和空目录分别给出可理解的状态，而不是空白或伪装成功。

### FR-02 Files：文件操作与反馈（P0）

**用户目标**：高频操作不繁琐，同时能理解冲突、进度和结果。

需求：
- 创建文件夹、重命名、复制、剪切、粘贴、移动、同目录 Duplicate、删除/移入适用回收机制，以及已支持的压缩/解压。
- 支持跨目录/跨窗格操作、内部拖拽、系统剪贴板互通及平台能力允许的跨应用拖放。
- 名称冲突时提供 Overwrite / Skip / Keep Both；对于多项任务可复用用户明确选择，不应无意义地反复询问。
- 无风险且用户意图明确的常规 Copy/Move 不增加重复确认；必要的删除、覆盖或不可逆风险必须说明。
- 任务中心展示进行中、已完成、失败、取消及部分完成；长任务应具备可理解的进度反馈。
- 操作完成后刷新相关目录；不得把部分成功伪称为全部成功。
- 告知用户当前操作使用的是系统回收站/废纸篓、应用自己的 Safe Trash，还是其他受支持的路径，不混淆其恢复承诺。
- 没有可用能力时清楚说明限制，不承诺必然可恢复。

验收：
- [ ] 一组包含多文件、嵌套文件夹及同名冲突的 Copy/Move 可完成和核对结果。
- [ ] Overwrite/Skip/Keep Both 分别按用户选择生效；目录冲突行为可解释。
- [ ] 任务取消、出错、部分完成后能看到真实结果与可用的恢复入口。
- [ ] Windows Explorer / macOS Finder 之间的剪贴板及可用拖放往返在实际系统上验证，而不只验证浏览器模拟。
- [ ] 与文件身份/原有 Journal/Restore 机制相关的正确性不因减少弹窗而被削弱。

### FR-03 Files：外部与已挂载存储（P0，按平台能力）

需求：
- 已挂载 USB、移动 SSD/HDD、SD 卡按系统实际能力展示、浏览和进行常规操作。
- 系统已挂载 SMB/NAS 与云盘客户端目录作为普通位置访问；断网、权限失败、设备拔出、只读或容量不足明确提示。
- 不因发现设备、浏览目录、请求缩略图而自动授权全盘索引或让云占位文件批量下载。
- 能力允许时提供系统级安全弹出；被系统拒绝时如实报告。

验收：
- [ ] 使用真实设备完成基本读写、异常断开/权限状态测试。
- [ ] 使用真实的受支持 SMB、已挂载云盘客户端检查在线/离线及占位文件行为。
- [ ] 未经授权不得将新设备加入 Global Search 或 Managed Library 范围。
- [ ] 实测资格和支持范围明确记录在 #487；未经验证不宣称“所有设备都兼容”。

### FR-04 Global Search（P0）

**用户目标**：快速找出所选范围内的文件，并知道搜索是否可信。

预期流程：
1. 用户在首次引导或 Settings 中明确授权一个或多个受支持本地来源。
2. 应用说明索引范围、索引进度、暂停/错误/未完成状态，默认采用 Smart Lean 低价值过滤。
3. 用户通过顶部搜索框或 Ctrl/⌘+K 输入关键词，看到与当前授权范围和索引状态一致的结果。
4. 用户可打开文件、定位所在文件夹，或继续使用 Files 处理。
5. 用户可以调整、暂停或关闭来源授权；取消授权后不继续把该范围当成可正常查询的现有数据。

边界和异常：
- 索引来源授权与 Windows 搜索相关后台能力默认启用是不同概念；**任何未授权来源不得因默认 ON 而被偷偷全盘扫描**。
- macOS 保留其现有平台默认关闭的策略，授权/启用时要向用户说明限制。
- 索引未完成、离线或不可用时不得把“未检出”显示为“肯定不存在”。
- Global Search 与 Files 当前文件夹搜索职责不同；不强行合成同一搜索引擎。
- 性能验收沿用项目已有 Search / Global Index 基准和真实环境证据；PRD 不另造缺少测量依据的 p95 数字。

验收：
- [ ] Windows 原生安装版完成授权、首次索引、文件创建/重命名/移动/删除后结果更新、取消授权及重新启用测试。
- [ ] macOS 明确实际可用能力、默认状态和平台限制，并做真实主机验证。
- [ ] 搜索失败、索引部分完成、用户未授权时提示准确；用户可以从结果返回 Files。

### FR-05 AI Organize：一次性智能整理（P0）

**用户目标**：一次查看整批文件的建议分类，按组决定是否执行，而非逐文件审批。

预期流程：
1. 从 Files 当前目录、选中项或 File Basket 进入 Organize，也可从专用入口选择一次性支持范围。
2. 仅在开始该任务时说明模型/提供方就绪情况，申请对应的 AI 数据共享授权；普通 Files 功能无须授权。
3. 获得文件名称、扩展名、大小、时间等已授权数据后，生成分组方案。
4. 每组展示数量、目标位置、主要理由及例外。用户可按组接受/排除，必要时改目标或展开单项。
5. 一次性确认准备执行的实际变更；执行后给出分组结果、异常和 History/Restore 入口。

约束：
- 当前 One-off Organize 的已实现边界为**所选文件夹直接子项、最多 100 条、元数据分析、不递归整理子文件夹**；产品要在入口处说明限制，不能把它包装成支持任意大规模/递归整理的成熟能力。
- 未配置模型或当前授权不允许时，应解释原因，并允许用户退出任务；不得暗中调用远端模型或自动启用旧规则作为 AI 替代。
- AI 建议不能越过真实文件身份、冲突、预览、确认、Journal 和 Restore 规则；具体执行以现有后端权威为准。
- 不要求用户把文件永久加入 Managed Library 才能发起一次性整理。

验收：
- [ ] 无 Managed Library 的普通文件夹可发起任务。
- [ ] 生成按组方案，能够排除一组、修改目标、处理异常，再执行剩余部分。
- [ ] 用户能知道 AI 使用了哪些类型的数据；拒绝授权后不继续生成语义建议。
- [ ] 结果与实际操作一致，可从 History 查看并恢复符合条件的操作。
- [ ] 超出 100 条或非支持范围时给出明确边界，不发生静默截断或部分文件被当作全部处理。

### FR-06 AI Cleanup：有解释的批量清理（P0）

**用户目标**：知道哪些占空间的内容值得清理、风险是什么、能释放多少空间，以及如何找回。

预期流程：
1. 用户选择受支持的清理范围。
2. 确定性检测器生成候选事实、类别、预估空间和现有执行资格。
3. 可在独立 Cleanup AI 授权下对有关候选进行语义解释，形成按类别/风险组织的整体方案。
4. 至少清晰区分：可批量清理、需要用户判断、受保护或不应清理。保留不处理的选项。
5. 用户可按组选择、查看例外，再进行一次明确的批量确认。
6. 仅将符合现有可执行条件的对象送入 Safe Trash，并呈现结果、失败、部分完成及恢复入口。

约束：
- 确定性检测和符合条件的 Safe 清理不应强制依赖 AI Key；没有 AI 时不伪称进行了 AI 语义判断。
- AI 不得凭“高置信度”提升删除资格、覆盖保护项判断，不能自动永久删除。
- 预计可释放空间是估算，不是尚未执行的实际回收结果。
- AI 数据共享、路径信息与模型费用/资源边界须对用户透明。
- 清理执行继续使用现有 Finding、Preview、Safe Trash、Journal 和 Restore 体系。

验收：
- [ ] 无 AI 配置时可完成受支持的确定性扫描和 Safe 处理。
- [ ] AI 授权与普通整理的授权相互独立；缺失授权不会偷偷请求模型。
- [ ] 受保护项、需判断项不会混入默认可执行批次。
- [ ] 已处理、跳过、失败及可恢复记录与实际执行一致。

### FR-07 History / Undo / Restore（P0）

**用户目标**：任何支持恢复的文件变更都有清楚的结果记录，不必猜测刚才改了什么。

需求：
- 可按时间查看文件操作与清理任务，能定位原始任务、目标范围、结果和失败项。
- 对已有支持的 Copy/Duplicate/Move/Trash 等提供相应 Undo/Restore 入口；明确哪些操作不支持，为什么。
- 文件已被外部修改、目标发生冲突、设备离线或权限变化时，拒绝或提示处理方法，不能偷偷覆盖新的用户数据。
- 快捷键撤销与 History 恢复的语义应一致，避免不同入口做出相互矛盾的修改。
- 对不具备完整恢复资格的外部文件系统/跨应用操作，不作超出能力的承诺。

验收：
- [ ] 普通复制/重复、移动、受支持的清理任务在实际文件系统上能核对 History 和恢复结果。
- [ ] 修改过的目标、同名冲突及不可恢复情况能得到明确说明。
- [ ] 部分执行失败后的 History 不伪造完整成功。

### FR-08 Settings、授权与资源透明度（P0）

用户应能在 Settings 找到：Global Search 来源与状态；AI 提供方/凭据/授权；文件操作与恢复相关设置；必要的诊断信息。

原则：
- AI 是按需能力，不是日常 Files 使用门槛。
- 各类授权按现有产品/平台能力区分，不能因一次打开文件而等价于长期扫描或远端 AI 分享。
- 空闲时不主动执行未授权的 Managed Scan、内容分析或无意义高频轮询。
- 资源占用、索引覆盖和任务进度的文案必须真实；性能预算沿用当前工程门禁，不在此另建体系。

## 5. 关键跨功能用户旅程

| 用户旅程 | 起点 | 可验收的用户结果 |
| --- | --- | --- |
| J-01 第一次使用 | 全新安装、没有 AI Key | 跳过引导，立即浏览本地文件，打开文件并操作 |
| J-02 多目录管理 | 两个及以上目标目录 | 多窗格定位 → 多选 → 复制/移动 → 处理冲突 → 看见结果 |
| J-03 全局找文件 | 用户明确授权的本地来源 | 看到索引状态 → 输入关键词 → 定位结果 → 打开/处理文件 |
| J-04 清理下载目录 | 含多种类型的实际文件夹 | 授权必要 AI → 分组方案 → 排除例外 → 一次执行 → History |
| J-05 释放空间 | 实际可分析的清理范围 | 扫描事实 → 风险分组 → 选择可清理项 → Safe Trash → 恢复 |
| J-06 错误恢复 | 已完成的可恢复操作 | 在 History 找到正确任务 → 恢复 → 验证实际文件 |
| J-07 外部存储工作 | USB / SMB / 已挂载云盘客户端 | 浏览、操作和断连反馈符合系统实际能力；不隐式索引或批量下载 |

这些旅程是验收用例的**用户语言版本**；具体主机、设备、测试证据与 PASS/FAIL 归 #487，不在 PRD 重建 QA 台账。

## 6. 交互与非功能体验原则

1. **先完成任务，再暴露技术细节**：先让用户看到文件、分组、目标和结果，再按需提供高级设置和诊断。
2. **无意义确认最少**：明确的普通复制/移动不叠加多层确认；真正有风险或影响不可逆的动作保留必要确认。
3. **状态诚实**：区分未授权、索引中、部分结果、离线、权限不足、任务失败、部分成功、已完成和可恢复。
4. **反馈及时**：长任务持续展示阶段与进度；取消后不将仍在执行或部分完成的任务伪装成完全停止/成功。
5. **可读、可操作、跨平台一致**：提供明确键盘焦点、提示、空状态及布局响应；Windows/macOS 适配各自习惯，不机械复制。
6. **本地优先**：普通文件管理不依赖云端 AI 或网络连接；AI 使用时说明实际数据路径和授权。
7. **性能以体验验收为入口**：首屏文件可见性、目录切换、列表滚动、多窗格、文件复制、搜索索引需在真实主机验证；数字门槛取现有已批准的专项基准，不在产品 PRD 中虚构新数字。

## 7. v1.0.0 产品验收定义

### 7.1 必须证明的事情

- 支持的平台**真实安装版**能够完成 J-01 至 J-07 中与平台/设备能力相符的路径。
- 用户无需建立 Managed Library 或配置 AI 即可完成 Files 基础任务。
- 文件操作确实落到真实文件系统，冲突、取消、进度、History/Restore 与事实相符。
- Global Search 的授权、索引覆盖、失败/部分结果与实际状态一致。
- AI 整理与清理在有授权时展示可审阅方案；无授权/无 Key 时表现正确，不假装已有 AI 判断。
- 文件管理器在 Windows/macOS 的高频使用路径可理解、可用；不能仅凭 Chromium 视觉回归宣称原生体验通过。
- 明确列出仍存在的 P0 缺口或未验证项；候选版本未获得发布资格时不得称为 Released。

### 7.2 评价维度（建议记录，不捏造已有成绩）

| 维度 | 观察方式 |
| --- | --- |
| 首次价值 | 用户能否在不配置 AI/索引的情况下独立进入 Files 并打开文件 |
| 任务完成率 | J-01～J-07 核心场景 PASS / FAIL / BLOCKED / UNVERIFIED |
| 操作负担 | 高频 Copy/Move/Organize/Cleanup 完成一次任务所需的额外确认及回退次数 |
| 可理解性 | 用户能否解释当前搜索范围、清理风险、任务是否成功以及如何恢复 |
| 跨平台真实表现 | Windows 安装版、Apple Silicon macOS 安装版、设备与文件系统场景 |
| 性能与稳定性 | 复用现有 Search、Copy、多窗格、Zen Zero 等基准和原生长期运行记录 |

这些是**建议的产品评价维度**，不是已经采集到的数据，也不是额外的流程门禁。

## 8. 已知边界与待确认事项

以下不阻止创建 PRD，也不是要求再启动研究 PR；在真实产品验收时针对性明确即可。

| 项目 | 当前依据 | 需要在产品交付时明确 |
| --- | --- | --- |
| 搜索默认行为 | ADR-0016、#512、Global Index 相关 PR | 用户感知的“默认启用”与后台能力默认开关、来源授权不可混淆 |
| One-off Organize 规模 | 当前直接子项上限 100，元数据、非递归 | v1.0.0 对限制的显式提示是否足够；扩大规模属于另行排期的功能决策 |
| 删除语义 | 系统回收站/废纸篓与 Fylura Safe Trash 并存 | 用户可明确识别实际删除路径和恢复边界 |
| 设备与云盘 | #553 及 #487 | Windows/macOS 真实设备和已挂载目录支持矩阵，而非通用“完全支持” |
| UI 高保真 | #574 原型与生产实现 | 设计达到目标不等于全部安装版实机已通过 |
| AI 产品价值 | #541、#542 及后续实现 | 需要真实文件集检验方案质量、异常处理和用户是否觉得省事 |
| 目标用户假设 | 产品方向与当前经验 | 以后通过试用反馈验证，不把主观假设写成用户调研结论 |
