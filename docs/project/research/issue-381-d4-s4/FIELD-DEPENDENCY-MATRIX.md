# D4-S4 field dependency and writer/consumer inventory

**Scope snapshot:** frozen D4-S3 product source at ad85df097d7a8425df01e1a95829c38fd17dd4d6. The file_sources, physical identity, claim, generation, Manifest, pointer, and lease relations are research-candidate tables from D4-S2/S3; they do not yet exist in product Schema 37 and have no production Rust readers or writers. Their actual research readers/writers are named below. Production Schema 37 still has files.path UNIQUE and files.is_stale as the File Library visibility contract.

The source line numbers below refer to the frozen parent tree. “Invalidate” means the future Manifest cannot remain the current visibility authority without either rejecting the mutation or advancing an explicit authority version. It does not mean erase a history row.

## Field-level independence boundary

The authority seal covers run/root/source/path/physical identity/claim/generation/projection/pointer evidence only. It does not freeze ordinary files.context, tags, notes, classification metadata, saved views, or user decisions. files.path/name are different: they alter FTS-visible identity and must move with a new path entry and Manifest pointer in one transaction. The existing FTS trigger is unconditional on UPDATE, so even context-only writes rewrite the external-content FTS row; that behavior is a performance issue, not authority evidence.

## Revision domain summary

| Revision / token | Owner domain | Mutations that advance it | Cursor/publication effect |
|---|---|---|---|
| scan_runs.revision, lease_token | scan worker ownership/checkpoint CAS | admission, run claim, batch, phase, cancellation/finalization | Reject stale worker; not a global source identity. Terminal coverage fields are frozen after publication. |
| scan_roots.revision | broad root lifecycle CAS | admission and root lifecycle/Watcher methods | Compared against generation at publication only. A production Manifest contract needs a distinct root configuration revision. |
| scan_roots.watcher_revision / watcher_applied_revision | filesystem event stream | Watcher batch begin/complete/recovery | Any new event invalidates current seal; only a new covered generation restores visibility. |
| candidate file_sources.source_revision | source identity/status | explicit source-state mutation or claim revocation | Must be included in the Manifest source evidence seal; change invalidates prior current view and Cursor. |
| candidate Manifest pointer (manifest_id, revision) | published File Library projection | trusted atomic pointer CAS | Cross-transaction Cursor with a different pointer is rejected. |
| D4-S4 candidate authority_revision | transitive evidence validity | authorized change to source/root/claim evidence | Cross-transaction Cursor with prior authority revision is rejected, even if pointer row is unchanged. |
| tag/file library query revisions | user tag and query selection | tag writes and library content changes | Independent from authority seal; used for selection CAS, not source identity. |
