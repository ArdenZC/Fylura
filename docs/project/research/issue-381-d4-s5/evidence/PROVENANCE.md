# Evidence provenance

## D4-S4 original log

The frozen D4-S4 commit does not contain `docs/project/research/issue-381-d4-s4/evidence/transitive-evidence-run.log` in its Git tree. The D4-S4 `evidence/SHA256SUMS` references the file with SHA-256:

```text
674d6a82e1b123e3f5976e1c922df347cd897a0d01d4005f2622550ab79a2782
```

The original 1,060-byte ASCII log remained in the local D4-S4 working tree but was ignored by `.gitignore` rule `*.log`; it was not a tracked path in the frozen parent commit. Its raw bytes were copied, without parsing or reserialization, to `evidence/archive/d4-s4-transitive-evidence-run.log`. The archived copy hashes to the original recorded SHA-256 above. This is an archival copy of the retained original file, not a reconstruction from the JSON results.

The archive is independently included in `SHA256SUMS`. `INPUTS.json` records the frozen parent Git-tree absence, original recorded hash, archived path, and `reconstructed: false`.

## D4-S5 run

`scoped-authority-results.json` is generated by the checked-in `harness/run.py` against the checked-in SQL prototype and the accepted D4-S2/S3/S4 harness inputs. `scoped-authority-run.log` is the direct stdout summary of that invocation. The JSON records the SQLite version/source ID and SHA-256 values for the schema and research harness inputs. It is not reconstructed from a prior JSON artifact.
