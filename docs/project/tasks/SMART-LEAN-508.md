# Smart Lean — Issue 508

Outcome: ship default low-value-file exclusion in Global Index, with explicit source authorization, conservative visibility and user controls. Authorized by [#508](https://github.com/ArdenZC/Zen-Canvas/issues/508); one [Draft #509](https://github.com/ArdenZC/Zen-Canvas/pull/509), based on master `0626e2f`. No merge or release before Owner review.

Users open Settings → Global index & AI management → Search coverage. New profiles select Smart Lean; existing development profiles retain Broad. Enable each source explicitly (Windows still requires its per-volume authorization dialog). macOS discovers local volumes by native volume UUID, with independent scoped Spotlight/FSEvents lifecycles and default disabled sources. Select Custom to add an existing, permitted folder Include/Exclude rule, preview the bounded sample, then Apply and rebuild. Broad restores performance-excluded coverage after rebuild; permissions and protected boundaries still apply. Existing source rebuild controls recover interrupted or incomplete indexing.

Smart Lean v1 recognizes npm/pnpm/yarn dependencies with project/installation markers, Python virtual environments, Rust/CMake generated trees and native known cache locations. It never excludes generic directory names alone. Uncertain identity, aliases/hardlinks, permissions and cloud availability remain visible with partial coverage. Includes override performance rules in Custom; deepest path wins and exclusion wins ties. Rules bind source, volume and native directory identity. Exclusion grants no Managed, AI, content or mutation authority.

SQLite remains the sole search authority. Schema46 adds coverage metadata and sparse lookup indexes. New excluded regular files create no ordinary/FTS rows; hidden minimal directory identities remain in the existing repository for parent resolution. Previously indexed rows and all references/user metadata are retained. Policy CAS atomically fences old writers and persists rebuild intent. Pending sources hide old-policy search results. Reconciliation retires at most 512 entries per transaction and restarts from durable row state; provider-owned rebuild/backfill uses the existing operation owner/revision and retry contracts. Native enumeration itself is not reduced.

Preview is a sample of at most 1,000 persisted candidates, not a complete impact total. Coverage counters are candidate observations (including repeats/minimal ancestors), not distinct filesystem totals. Current uncertainty/completeness derives from active repository state independently of those cumulative counters. Source health is separate. A filtered-empty search never asserts physical absence.

Validation is in progress in Draft #509: focused frontend tests, native Windows/macOS policy/recovery tests, normal CI, and paired controlled-filesystem admission benchmarks at 1k/100k or larger. Benchmarks use three rotating rounds of the ungated repository writer control and Broad/Smart Lean, with native fixture file IDs, 40% known low-value candidates, row/FTS/page counts, native-observer metadata accessor attempts, sampled process RSS and bounded policy-switch/reindex cost. They do not measure raw MFT enumeration, Apple Spotlight workload or native wake cycles. Final exact-source results and remaining native acceptance gaps belong in the Draft PR; no production-ready claim until those results support it.

Safe native acceptance: use a task-owned fixture root on an explicitly authorized disposable test volume/profile. Create project markers and dependency/build files plus ordinary `Windows`, `build`, `AppData`, source/docs/log/Unicode lookalikes. Verify Smart Lean search, Custom Include and Broad restoration, revoke/re-enable, included↔excluded moves, interrupted rebuild/restart and permission recovery. Never authorize or scan Owner disks for automated QA. Global Search ranking/performance work, Managed Scan rewrites and old installer upgrades remain out of scope.
